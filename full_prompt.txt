# Build a Production-Ready Consumer Relationship Management System

## 1. Project Overview

Build a modern, responsive **Consumer Relationship Management System (CRM)** using **Django**.

The system should be designed around a large multi-brand retail business similar in concept to **Vijay Sales**, where customers purchase products across multiple brands and categories.

The CRM should provide:

- Customer account management
- Customer purchase history
- Product and brand management
- Product category management
- Invoice/order management
- Warranty management
- Complaint/ticket management
- Service request management
- Customer communication history
- Customer feedback and ratings
- Customer notifications
- Admin dashboards
- Customer dashboards
- Staff/service-agent dashboards
- Reports and analytics
- Role-based access control
- Audit/history tracking

The system must be designed as a **scalable modular application**, not as a single monolithic page.

---

# 2. Technology Stack

Use:

### Backend
- Python 3.x
- Django
- Django ORM
- Django authentication
- Django REST Framework where an API layer is useful
- SQLite for initial development
- Structure the project so PostgreSQL can easily be used in production

### Frontend
- Django Templates
- Tailwind CSS via CDN
- Vanilla JavaScript where possible
- Alpine.js via CDN may be used for lightweight interactivity if useful
- Chart.js via CDN for dashboards/charts

Do NOT introduce React/Vue/Angular unless absolutely necessary.

The application should primarily use:

**Django + Django Templates + Tailwind CSS + JavaScript**

# 3. Environment Setup

Create a Python virtual environment.

Example:

```bash
python -m venv venv
```

Activation:

Windows:

```bash
venv\Scripts\activate
```

Linux/macOS:

```bash
source venv/bin/activate
```

All Python dependencies must be installed inside the virtual environment.

Create:

```text
requirements.txt
```

and maintain all dependencies there.

The project should include a clear README containing:

- Installation instructions
- Virtual environment setup
- Dependency installation
- Database migration
- Superuser creation
- Development server startup
- Production deployment guidance
- Environment variable configuration

Do not install Python packages globally.

# 5. User Roles

Implement role-based access control.

Minimum roles:

### Super Administrator

Full system access.

Can:

- Manage users
- Manage roles
- Manage customers
- Manage products
- Manage brands
- Manage categories
- Manage orders
- Manage warranties
- Manage complaints
- Manage service requests
- View reports
- Configure system
- View audit logs

### CRM/Admin Staff

Can:

- Manage customers
- View purchases
- Create/update complaints
- Assign complaints
- Manage customer interactions
- View warranties
- Manage service requests
- Generate reports

### Service Agent

Can:

- View assigned complaints
- Update complaint status
- Add service notes
- Schedule service
- Update service status
- Upload service documents/photos
- Communicate with customer

### Sales Staff

Can:

- View/create customers
- View products
- Record purchases
- View customer purchase history
- Register warranty

### Customer

Can:

- Manage own profile
- View purchases
- View invoices
- View warranties
- Register products
- Raise complaints
- Raise service requests
- Track complaint status
- View communication history
- Submit feedback
- View notifications

Use Django Groups and Permissions wherever appropriate rather than hardcoding role checks throughout the application.

```text

    ↓
Order
    ↓

    ↓

    ↓
Brand
    ↓
Category
```

And:

```text
Customer
    ↓
Warranty
    ↓
Product / Serial Number
```

And:

```text
Customer
    ↓
Complaint
    ↓
Service Request
    ↓
Technician
```

Use proper:

- ForeignKey
- OneToOneField
- ManyToManyField

Add indexes to fields frequently searched:

```text
customer_id
mobile
email
order_number
invoice_number
serial_number
ticket_id
SKU
```

Use unique constraints where appropriate.

# 44. Soft Deletion

For important business records, avoid physically deleting data.

Instead support:

```text
is_active
deleted_at
deleted_by
```

Especially for:

- Customers
- Products
- Orders
- Tickets
- Warranties

Historical transactions should never disappear because someone deleted a record.
